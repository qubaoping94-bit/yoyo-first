# youyou-business-ai-frontdesk 使用说明

> **最简单调用方式——安装并配合优优无机板样例库使用，直接复制下面这句话：**

```text
用 $youyou-business-ai-frontdesk 查询演示数据 ORDER-演示-001，汇总客户项目、商品数量、金额、实际到账、欠款、备货、发货物流、签收验收、售后、负责人和下一步；只读，不写入。
```

官方仓库：[qubaoping94-bit/yoyo-first](https://github.com/qubaoping94-bit/yoyo-first/tree/main/skill-packs/youyou-business-ai-frontdesk)

---

## 一、它是什么

这是优优无机板合作商经营服务知识库样例的专用 AI 前台。它按现实业务意图在 40 个工作流之间路由，展示合作商、客户项目、选品样品、报备、报价、订单、付款、实际到账、备货、分批发货、物流、签收、验收、欠款、售后、责任复核、结案回访和经营查询。

它是“企业实际样例 Skill”，不是任意合作商的通用模板。给其他合作企业建立正式知识库时，应使用 [`partner-sales-service-ai-frontdesk`](../partner-sales-service-ai-frontdesk)。

## 二、核心能力

- 识别现实语言中的唯一业务意图，并使用对应工作流的必需输入、自动字段、确认字段、公式、前置条件和写入联动。
- 写业务固定为“描述或上传 → 四区预览 → 确认写入”。未确认、修改中、取消或权限不足时正式记录增量为 0。
- `WF24` 是只读查询例外，不创建事件、不更新状态卡，也不要求确认写入。
- 严格区分付款凭证与实际到账、签收与验收、售后受理与责任认定、处理完成与结案。
- 主档唯一匹配才自动带出；多匹配列候选，无匹配一次列全缺项。
- 查询使用严格 AND 条件，支持客户、订单号、日期、欠款、未发完、在途、超期、未验收和未结售后。
- 默认排除目录10、目录11和 DEMO；明确说“查询演示数据”后才纳入。

## 三、适合与不适合做什么

### 适合

- 给优优无机板合作商展示完整经营服务知识库的实际效果。
- 用演示订单讲解订单、到账、发货、物流、验收和售后的前后因果。
- 培训人员理解哪些字段能自动带出，哪些金额、地址、责任和状态必须人工确认。
- 演示客户、订单号和日期检索，以及管理汇总结果。

### 不适合或尚未验证

- 不适合直接改名后作为另一家合作商的正式库。
- 本技能包不包含完整优优无机板样例知识库笔记。
- 不会主动连接真实 CRM、物流、财务、开票或合同系统。
- 不支持在没有计划任务能力时宣称自动定时巡检。
- 尚未在真实 ima 在线环境完成安装和业务 E2E。

## 四、需要提供什么，会得到什么

### 输入

- 配套的优优无机板 B V6.2 R5 样例知识库。
- 自然语言描述、附件、客户、项目、订单号、日期或状态条件。
- 写业务时由当前账号提供确认，并受人员主档权限约束。

### 输出

- 四区预览：自动带出、本次识别、系统计算、需要确认。
- 确认后返回写入记录、关联订单、最新状态、下一步和查询方法。
- 查询时返回查询条件、结果、统计口径和来源，保持零写入。
- 异常提醒只列真实发生事项、负责人、截止时间和建议动作。

## 五、三条主要使用路线

### 路线 A：正常履约演示

使用 `ORDER-演示-001`，按时间展示客户、订单、交期、备货、付款与到账、发货、物流、签收、验收、售后和回访。

### 路线 B：变更或取消演示

使用 `ORDER-演示-002` 演示订单变更，使用 `ORDER-演示-003` 演示订单取消。不能把同一订单同时描述成正常履约、变更和取消。

### 路线 C：只读经营查询

使用客户、订单号、日期和状态进行严格 AND 查询；不存在、否定、互斥或错误日期应返回零命中或要求补充。

## 六、可直接复制的调用指令

### 1. 最简查询

```text
用 $youyou-business-ai-frontdesk 查询演示数据 ORDER-演示-001 的完整状态、负责人和下一步；只读，不写入。
```

### 2. 客户月度汇总

```text
用 $youyou-business-ai-frontdesk 查询演示数据中该客户2026年8月的全部订单，逐单显示订单号、日期、商品数量、应收、实际到账、欠款、已发未发、物流、验收和售后，并给出合计和来源；不要写入。
```

### 3. 模拟付款处理

```text
用 $youyou-business-ai-frontdesk 模拟处理这张付款凭证；先登记凭证预览，保持已付和未付不变。只有有财务权限的人确认实际到账后，才生成到账事件和更新金额。
```

### 4. 模拟售后处理

```text
用 $youyou-business-ai-frontdesk 模拟新增一条售后。先关联唯一订单和发货批次，责任保持待复核；售后受理、处理、责任认定、结案和回访必须分别记录。
```

### 5. 迁移为其他合作商

```text
不要修改优优样例 Skill。请改用 $partner-sales-service-ai-frontdesk，根据新合作商的企业、产品、人员权限、客户项目和收货点资料生成独立 SETUP 预览。
```

## 七、标准工作流程

1. 先建立或导入优优无机板合作商经营服务样例知识库。
2. 安装本 Skill。
3. 展示时明确说“查询演示数据”，避免默认排除 DEMO。
4. AI 识别唯一意图并读取该工作流合同。
5. 写业务时检查主档、前置状态、幂等键、阻断条件和权限，生成四区预览。
6. 由实际有权限人员确认金额、到账、发货、验收、责任和结案。
7. 查询使用 WF24 只读路线，不产生事件和状态更新。
8. 新企业正式建库时切换到 B 通用模板 Skill。

## 九、依赖与运行条件

- Codex 或兼容 `SKILL.md` 的 Agent。
- 配套优优无机板 B V6.2 R5 样例知识库；本仓库未包含完整样例笔记。
- 本 Skill 自身不要求 Python，也不要求网络。
- 真实外部接口必须另行授权、配置最小权限并完成审计。

## 十、限制、安全与隐私

- 源 Skill 明确保持 `EXTERNAL_WRITES_0 / NOT_PUBLISHED / REMOTE_RELEASE_HOLD / REAL_CUSTOMER_DATA_0`。
- 不要把真实客户资料、价格、合同、凭证、电话或账号提交到公开仓库。
- 行金额、应收、未付和未发必须按合同公式计算，不能凭语言猜测。
- 重复编号、负数、日期倒置、超发、超付、状态倒退和因果越级必须阻断。
- 查询按当前账号权限过滤，不能通过提示词扩大权限。

## 十一、常见问题

### 为什么查询不到样例订单？

默认排除 DEMO。请在问题中明确写“查询演示数据”。

### 为什么付款凭证没有更新已付金额？

凭证不等于到账。只有有权限财务人员确认实际到账后才能更新已付和未付。

### 为什么 Skill 描述里写 R4，而目录是 R5？

原始 `SKILL.md` frontmatter 保留了 R4 描述，但正文已经包含“R5 完整业务因果与演示编号”，配套目录和工作流合同来自已验收的 V6.2 R5 样例。本技能包保持原始 Skill 文件逐字节不变，并在这里公开说明版本差异。

### 如何给其他合作商使用？

使用 B 通用模板 Skill，不要在优优样例中写入另一家企业的正式资料。
