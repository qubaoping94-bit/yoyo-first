## 1. 目标与读者

把分散在 `SKILL.md`、README、示例、脚本、仓库和官网中的信息，转化为读者无需研究源码即可使用的 Markdown 指南。默认读者是会向 Codex、Claude Code 或其他 Agent 发自然语言指令，但不一定熟悉代码的人。

文档必须同时回答：

- 它是什么，解决什么问题；
- 能做什么、不能做什么；
- 最快怎样调用；
- 不同任务应选哪条路线；
- 需要提供什么，最后得到什么；
- 如何安装、验证和排错；
- 哪些链接、许可、安全和环境限制需要注意。

## 2. 来源与证据规则

为核心事实建立来源清单。优先级为：本地正式 `SKILL.md` → 同版本 bundled resources → 官方仓库/文档 → 官方站点/包注册表 → 源码或安全测试 → 明示推断。

必须核验的动态字段：版本、数量统计、兼容平台、安装命令、在线画廊/演示、仓库默认分支、许可证和废弃状态。

当不同来源冲突时：

1. 判断是否属于不同版本；
2. 采用当前 canonical source；
3. 在“版本与核验信息”中说明差异；
4. 无法判断时删去精确数字或标为“待官方确认”。

不要把示例效果描述成所有输入都能保证的结果。不要把依赖工具的通用能力自动算作 Skill 自带能力。

## 3. 第一屏规范

第一屏优先级固定：标题、可复制标签、自然语言调用代码块、官方在线资源、官方仓库。没有公开资源时删除对应项目，不要保留假链接。

最简调用句需包含目标 Skill 的精确名称、动作、核心产物。只有确实需要用户提供路径或 URL 时才保留一个清晰占位符。

## 4. 内容模块决策

### 默认必备

1. 它是什么
2. 核心能力
3. 适用场景与不适用场景
4. 输入与输出
5. 使用路线或工作模式
6. 可直接复制的调用指令
7. 标准工作流程
8. 安装、发现与验证
9. 限制、安全与隐私
10. 官方地址、版本与核验信息

### 有证据才加入

- 在线画廊、动态示例、演示视频；
- CLI、MCP、API、插件或 Provider；
- 模板、预设、组件、命令或参数明细；
- 价格、许可证、商业使用规则；
- 本地服务启动方式；
- 兼容矩阵、故障排查、卸载和更新；
- 与相近 Skill 的差别；
- 已验证成品案例。

### 应删除

- 没有事实内容的空章节；
- 重复表达；
- 面向 Skill 开发者但对使用者无用的内部细节；
- 未验证的“最佳”“自动”“一键”“全平台”等绝对表述；
- 聊天过程、临时判断和未经授权的私有地址。

## 5. 调用示例规范

至少提供以下四类中的三类；复杂 Skill 全部提供：

1. **最简调用**：一次完成最典型任务。
2. **推荐调用**：包含目标、质量标准、输入和交付格式。
3. **约束调用**：限定平台、尺寸、语言、技术栈、安全或禁止事项。
4. **继续修改**：基于现有产物修订，明确保留项和变化项。
5. **只分析不执行**：适用于可能产生外部写入或成本的 Skill。

每条指令应可复制、自然、具体，不要使用只有作者能懂的变量。必要占位符统一写成 `<目标路径>`、`<仓库 URL>` 或 `<输出目录>`。

## 6. 写作与格式规则

- 默认使用简体中文，保留命令、参数和产品专名原文。
- 先给结论和操作，再解释背景。
- 采用清晰的二级、三级标题；长文可加入目录，但不得挤占第一屏。
- 命令和自然语言提示分别使用带语言标识的代码块。
- URL 使用可点击的完整地址；本地路径使用绝对路径。
- 表格只用于比较、映射或兼容矩阵，避免为了整齐而堆表格。
- 对精确统计注明版本或核验日期。
- 对可选依赖使用“可选”“仅在……时需要”等准确措辞。

## 7. 完整性矩阵

| 维度 | 必查问题 |
|---|---|
| 身份 | 名称、作者/组织、canonical source 是否明确？ |
| 价值 | 解决什么问题，和底层工具有什么区别？ |
| 能力 | 每项能力是否有来源或可复现证据？ |
| 场景 | 适合与不适合的边界是否清楚？ |
| 输入 | 用户要提供哪些文件、网址、参数或授权？ |
| 输出 | 最终产物、格式、路径和证据是什么？ |
| 路线 | 模板、自定义、单功能或分析模式如何选择？ |
| 调用 | 是否有最简、推荐、约束、修改型指令？ |
| 安装 | 安装、发现、更新、本地验证是否准确？ |
| 在线资源 | 官网、仓库、画廊、演示是否为官方且可访问？ |
| 依赖 | 运行时、工具、账号、网络与平台条件是否说明？ |
| 风险 | 外部写入、费用、隐私、Secret、版权是否提醒？ |
| 限制 | 未支持或未验证的内容是否明确？ |
| 版本 | 日期、版本、统计和冲突是否可追溯？ |

## 8. 交付验收门禁

### P0：缺一不可

- [ ] 首屏出现可直接复制的最简调用句。
- [ ] 完整读取目标 `SKILL.md`，并检查直接相关资料。
- [ ] 能力、安装命令和在线地址没有臆测。
- [ ] 文档包含能力、场景、输入输出、工作流、调用示例、限制和来源。
- [ ] 没有 Secret、私有凭据、未清理占位符或断裂代码块。
- [ ] Markdown 文件可用 UTF-8 打开，输出路径明确。

### P1：质量增强

- [ ] 动态信息已通过官方当前来源核验，并记录核验日期。
- [ ] 复杂功能提供路线选择建议和至少四类调用示例。
- [ ] 安装后验证、常见问题和更新方式清楚。
- [ ] 链接可点击，本地命令可执行或已标注未运行。
- [ ] 文档语言贴合目标读者，没有 README 式堆砌。

### P2：可维护性

- [ ] 文档标明最后核验日期和依据。
- [ ] 易变数字集中在一个章节，便于未来更新。
- [ ] 未验证项单独列出，不与已确认事实混写。
