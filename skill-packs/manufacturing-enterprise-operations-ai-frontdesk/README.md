# manufacturing-enterprise-operations-ai-frontdesk 使用说明

> **最简单调用方式——安装后直接复制下面这句话：**

```text
用 $manufacturing-enterprise-operations-ai-frontdesk 根据我上传的制造企业资料生成首次启用预览；先列全缺项和冲突，正式写入保持 0，等有“企业启用确认”权限的管理员一次确认。
```

官方仓库：[qubaoping94-bit/yoyo-first](https://github.com/qubaoping94-bit/yoyo-first/tree/main/skill-packs/manufacturing-enterprise-operations-ai-frontdesk)

## 一、它是什么

这是面向制造企业的经营知识库 AI 前台。它把销售、客户、订单、测量设计、BOM、采购、生产、质检、入库、发货物流、安装验收、财务回款、售后和经营查询统一到一套有权限、有确认、有历史快照的工作流中。

它不是 ERP，也不会凭空连接企业系统。它负责识别用户意图、读取企业主档或历史交易快照、生成预览、拦截缺项和越权操作，并在有权限人员确认后按合同处理业务。

本技能包内的工作流合同包含 54 个唯一工作流，核验日期为 2026-08-11。

## 二、核心能力

- 使用 `A-MFG-PROFILE-1.1.0` 企业启用档案统一保存企业、产品单位、员工角色权限、客户项目、供应商、仓库、物流、编号规则和外部接口状态。
- 自动计算唯一运行模式：资料不完整或未授权为 `SETUP`，完整授权的样例资料为 `DEMO`，完整授权的正式资料为 `LIVE`。
- 首次启用只生成配置预览，不创建正式业务记录；管理员不需要手工编辑 JSON。
- 后续业务优先继承订单、合同、图纸、BOM、价格、地址等历史交易快照，避免当前主档覆盖当时事实。
- 写业务遵循“描述或上传 → AI 预览 → 有权限人员确认”；查询保持只读。
- 默认排除 DEMO 数据；只有用户明确要求查询演示数据时才纳入。
- ERP、物流、财务、OCR 未连接时明确提示，并回退为上传凭证或人工提供已核实事实。

## 三、适合与不适合做什么

### 适合

- 给木门、家具、板材加工、机械加工等制造企业建立内部经营知识库。
- 统一客户、订单、生产、采购、质检、交付、回款和售后记录格式。
- 让员工用自然语言新增业务、查看预览、确认写入或查询经营状态。
- 把同一模板复制给不同制造企业，再用各自企业资料完成启用。

### 不适合或尚未验证

- 不能代替 ERP、财务软件、WMS、物流平台或法定会计凭证。
- 没有真实接口授权时，不能声称已读取实时库存、物流轨迹或银行到账。
- 不能脱离配套的 A 类制造企业知识库笔记独立完成全部业务落库。
- 尚未在真实 ima 在线环境完成安装、权限、写入、检索和回滚 E2E。

## 四、需要提供什么，会得到什么

### 首次启用需要提供

- 企业名称、业务类型、时区和币种。
- 产品编号、名称、规格、单位和价格政策。
- 员工账号、姓名、角色和权限；至少一名人员具有“企业启用确认”权限。
- 订单与生产编号规则、启用的业务流程、外部接口连接状态。
- 已启用业务涉及的客户项目、供应商、仓库和物流资料。
- 原始资料来源、文件哈希、抽取时间以及需要管理员裁定的冲突。

### 输出

- 企业启用预览、缺失字段、冲突和配置版本。
- `SETUP`、`DEMO` 或 `LIVE` 唯一模式。
- 业务办理时的自动带出区、本次识别区、系统计算区和人工确认区。
- 确认后的业务记录、关联对象、最新状态、下一步和查询方法。

## 五、三种运行模式

### SETUP

企业资料不完整、确认人不存在、权限不足或来源证据不完整时使用。正式写入必须为 0。

### DEMO

使用完整且经授权确认的虚构样例资料。用于培训和演示，默认不进入正式查询结果。

### LIVE

只有完整的 `FORMAL` 企业资料通过权限确认后才允许进入。进入 LIVE 不代表所有操作自动写入；每项高风险业务仍按各自工作流要求确认。

## 六、可直接复制的调用指令

### 1. 首次启用

```text
用 $manufacturing-enterprise-operations-ai-frontdesk 读取我刚上传的企业介绍、产品表、员工权限表、客户项目表和编号规则，生成企业启用预览。一次列出所有缺项和冲突，不要创建正式业务记录。
```

### 2. 新增订单

```text
用 $manufacturing-enterprise-operations-ai-frontdesk 新增一张客户订单。先从已确认主档带出客户、项目、产品、单位和价格版本，再让我填写本单变化的数量、交期和特殊要求；计算金额后给出预览，未经确认不要写入。
```

### 3. 只读查询

```text
用 $manufacturing-enterprise-operations-ai-frontdesk 查询客户“远航装备”本月所有订单，汇总订单号、日期、商品数量、应收、已收、未收、生产、发货、安装、验收、售后、负责人和下一步；只读，不写任何记录，默认排除 DEMO。
```

### 4. 带安全约束办理

```text
用 $manufacturing-enterprise-operations-ai-frontdesk 处理这张付款凭证；必须区分“收到凭证”和“财务确认到账”，保留附件来源与读取时间，权限不足时只保留预览，不得更新已收金额。
```

### 5. 修改现有配置

```text
用 $manufacturing-enterprise-operations-ai-frontdesk 根据新产品表生成企业档案的新版本；保留历史订单中的原价格、单位和产品快照，不覆盖旧版本，先给我差异预览。
```

## 七、标准工作流程

1. 将配套 A 类知识库笔记导入或建立到目标知识库。
2. 安装本 Skill。
3. 上传企业资料，让 AI 抽取、去重并列出缺项和冲突。
4. 由拥有“企业启用确认”权限的管理员核对一次启用预览。
5. 启用后，员工只需描述业务或上传凭证；AI 自动带出稳定字段。
6. 变化字段、高风险事实和权限事项继续由实际人员确认。
7. 用客户、订单号、日期或状态进行只读查询和汇总。

## 九、依赖与运行条件

- Codex 或兼容 `SKILL.md` 的 Agent。
- 运行 `render_enterprise.py` 需要 Python 3.9 或更高版本。
- 需要配套的 A 类制造企业知识库笔记和根目录 `企业启用档案.json`。
- 外部接口为可选能力；未连接时仍可用人工上传资料的降级路线。

## 十、限制、安全与隐私

- 不要把真实客户资料、价格、合同、账号或凭证提交到公开 GitHub 仓库。
- 启用确认账号必须存在于员工权限主档，并真实拥有“企业启用确认”权限。
- 付款凭证不等于到账，签收不等于验收，售后受理不等于认责或结案。
- 查询按当前账号权限过滤；用户不能通过提示词扩大自己的权限。
- 历史业务记录只追加新事件或新版本，不直接重写旧事实。

## 十一、常见问题

### 为什么一直处于 SETUP？

检查企业、产品、人员权限、编号规则、启用流程、来源证据和确认快照是否完整；只填写 `confirmed=true` 不能绕过权限门。

### 为什么查询不到演示订单？

默认排除 DEMO。需要在查询中明确写“查询演示数据”。

### 安装 Skill 后为什么还不能直接办理订单？

本 Skill 需要配套知识库笔记和企业启用档案。只安装 Skill 不会自动创建完整企业知识库。
