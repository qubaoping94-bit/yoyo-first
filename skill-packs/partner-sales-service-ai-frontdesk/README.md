# partner-sales-service-ai-frontdesk 使用说明

> **最简单调用方式——安装后直接复制下面这句话：**

```text
用 $partner-sales-service-ai-frontdesk 根据我上传的合作商企业资料生成首次启用预览；自动带出稳定主档，一次列出缺项和冲突，正式写入保持 0，等待有权限管理员确认。
```

官方仓库：[qubaoping94-bit/yoyo-first](https://github.com/qubaoping94-bit/yoyo-first/tree/main/skill-packs/partner-sales-service-ai-frontdesk)

## 一、它是什么

这是面向品牌方、经销商、区域合作商、工程合作商和渠道服务商的经营服务知识库 AI 前台。它覆盖合作商、客户项目、选品样品、报备、报价、订单、付款与到账、备货、发货物流、签收验收、欠款、售后、责任复核、结案回访和经营查询。

它把“员工描述业务”转换为标准业务预览，并把不会变化的企业资料自动带出，把金额、地址、到账、责任等关键事实留给有权限人员确认。

本技能包内包含 40 个唯一工作流，核验日期为 2026-08-11。

## 二、核心能力

- 使用 `B-PARTNER-PROFILE-1.0.0` 统一管理企业、产品或服务、人员权限、合作方、客户项目、收货点、仓库、承运商和编号规则。
- 使用 `SETUP / DEMO / LIVE` 三种互斥模式，资料不完整或权限不足时保持正式写入 0。
- 自动带出合作商、客户、项目、产品、收货点和历史交易快照，减少重复填写。
- 严格区分付款凭证与实际到账、发货与物流、签收与验收、售后受理与责任认定、处理完成与结案。
- 查询按客户、订单号、日期、状态、欠款、未发完、在途、未验收和未结售后进行只读汇总。
- DEMO 默认排除，外部 CRM、物流、财务和 OCR 未连接时明确降级。

## 三、适合与不适合做什么

### 适合

- 为合作商建立简单直观的客户、订单、物流、回款和售后知识库。
- 把同一模板复制给不同合作企业，再填写各自企业主档。
- 让小白员工只填写每单变化的信息，其余内容由 AI 从主档和历史快照带出。
- 给管理人员提供客户、订单、日期和经营状态的只读检索汇总。

### 不适合或尚未验证

- 不能代替 CRM、ERP、财务、物流或开票系统。
- 未取得真实授权时不能读取银行到账、实时库存、实时物流或合同系统。
- 不能脱离配套 B 类合作商经营服务知识库笔记单独完成全部业务落库。
- 尚未在真实 ima 在线环境完成安装和业务 E2E。

## 四、需要提供什么，会得到什么

### 首次启用需要提供

- 企业名称、业务类型、时区和币种。
- 产品或服务编号、名称、规格、单位和价格政策。
- 员工账号、角色、权限以及一名拥有“企业启用确认”权限的管理员。
- 合作方、客户项目、收货点、仓库、承运商和启用流程。
- 报价、订单、到账、发货、售后编号规则。
- 来源文件、哈希、抽取时间和冲突项。

### 输出

- 企业启用预览、缺项、冲突、版本和唯一运行模式。
- 每次业务的自动带出、本次识别、系统计算和需要确认四个区域。
- 确认后的业务事件、状态、负责人、下一步和查询方法。
- 只读查询的条件、结果、统计口径和来源。

## 五、三种运行模式

### SETUP

用于缺资料、存在冲突、确认人无权限或正式资料尚未确认的情况。正式业务记录增量必须为 0。

### DEMO

用于完整且授权的虚构合作商样例。只做培训和展示，默认不进入正式经营查询。

### LIVE

用于完整的正式企业资料。只有企业启用 Gate 通过后进入，具体订单、到账、发货、验收和责任仍需按工作流确认。

## 六、可直接复制的调用指令

### 1. 首次启用

```text
用 $partner-sales-service-ai-frontdesk 读取我上传的企业介绍、产品价格表、员工权限表、客户项目表和收货点资料，生成企业启用预览；一次列出所有缺项和冲突，不要创建正式订单或其他业务记录。
```

### 2. 新增订单

```text
用 $partner-sales-service-ai-frontdesk 新增一张客户订单。请自动带出客户、项目、收货点、产品、单位和已确认价格版本，只让我确认本单数量、成交价格、订单日期、交期和特殊要求；先预览，确认后再写入。
```

### 3. 查询订单状态

```text
用 $partner-sales-service-ai-frontdesk 查询客户“东岸工程”2026年8月的全部订单，逐单显示订单号、商品数量、应收、实际到账、欠款、已发未发、物流、签收、验收、售后、负责人和下一步；严格只读，默认排除 DEMO。
```

### 4. 带业务边界办理

```text
用 $partner-sales-service-ai-frontdesk 处理这张付款凭证。只登记凭证和来源，不得直接更新实际到账；必须等有财务权限的人核验后，才允许更新已付和未付金额。
```

### 5. 修改企业主档

```text
用 $partner-sales-service-ai-frontdesk 根据新的收货点和价格表生成企业档案新版本；保留既有订单中的历史地址和价格快照，只展示差异，未经确认不要覆盖当前版本。
```

## 七、标准工作流程

1. 建立或导入配套 B 类合作商经营服务知识库笔记。
2. 安装本 Skill。
3. 上传一次企业、产品、人员、客户项目、收货点和编号资料。
4. AI 抽取、匹配、去重并生成启用预览。
5. 有“企业启用确认”权限的管理员一次确认。
6. 员工以后只描述业务或上传资料，AI 自动补全稳定字段。
7. 金额、日期、物流单号、实际到账、验收、责任等变化事实由相应人员确认。
8. 管理人员用客户、订单号和日期进行只读查询。

## 九、依赖与运行条件

- Codex 或兼容 `SKILL.md` 的 Agent。
- 运行 `render_enterprise.py` 需要 Python 3.9 或更高版本。
- 需要配套 B 类知识库笔记和 `企业启用档案.json`。
- CRM、物流、财务和 OCR 均为可选外部接口，默认未连接。

## 十、限制、安全与隐私

- 不要把真实客户、价格、合同、付款凭证、账号或联系方式上传到公开仓库。
- 付款凭证、实际到账、发货、签收、验收、责任和结案是不同事件，不能互相代替。
- 自动带出的每个字段应保留来源、版本和读取时间。
- 多个主档匹配必须让人选择；无匹配必须先补资料，不能猜测。
- 查询只能返回当前账号有权查看的字段。

## 十一、常见问题

### 为什么上传资料后仍不能启用？

检查企业、产品、人员权限、编号规则、来源证据和条件主档是否完整；确认账号必须真实存在并拥有“企业启用确认”权限。

### 为什么付款凭证上传后欠款没有变化？

这是正确行为。凭证只表示对方提交了付款证明，必须由有权限财务人员确认实际到账后才能更新已付和未付。

### 能不能直接给新合作商安装？

可以把它作为通用模板 Skill 使用，但必须同时建立配套 B 类知识库，并用该企业自己的资料完成 SETUP；不能复制其他企业的正式数据。
